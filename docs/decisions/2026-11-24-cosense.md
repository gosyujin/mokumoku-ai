# Cosense 連携の組み方(段階6)

## 背景

仕様書の段階6は「cosense-sync とツッコミの読み取り」。条件は次のとおり。

- 読み取りは認証なしの公開 API を使う(wake 側)。ツッコミの転記は、行の userId が人間のアカウントのものだけを採用する。
- `COSENSE_PAT` を持つのは cosense-sync の step だけ。書き込み先のプロジェクト名を定数で固定する。
- 編集 API の流れは「ページ取得 → 行 ID 指定の変更 → プレビュー → previewId で確定」。
- トークンは、既存のエージェント用アカウントのものを流用する(リスク受容済み)。

2026-11-24 に、公式の cosense-cli(helpfeel/cosense-cli 1.19.0)のソースと、公開 API の実際の応答を読んで分かったこと。

- 認証は `x-personal-access-token` ヘッダー。CLI は環境変数 `COSENSE_PAT` を読む。
- 仮の適用は `POST /api/pages/v2/{project}/page-edit-for-ai/preview`(本体は `{pageId?, changes}`)、確定は `.../submit`(本体は `{previewId}`)。previewId は1回限りで、約5分で失効する。
- 変更は `{_insert: 行ID | "_end", lines: {id, text}}` と `{_delete: 行ID}` の並び。pageId を付けなければ新しいページになり、最初の行がページ名になる。同名のページがあると、サーバーが別の名前を付ける。
- `GET /api/pages/{project}/{ページ名}` は、認証なしで行ごとの `userId` を返す。ページの一覧とメンバーの一覧も、認証なしで読める。
- CLI は npm のパッケージで、`tsx` に依存している。
- プロジェクトのメンバーは gosyujin と satoca の2人。

## 判断

- **cosense-cli は使わず、API を直接呼ぶ**(`tools/lib/cosenseApi.ts`)。外部依存を足さない決まりのため。また、トークンを持つ step で動くコードを、このリポジトリの中だけにするため。
- **アカウントの割り当て**(2026-11-24 にユーザーが決めた): gosyujin が人間、satoca がエージェント用。userId は `tools/lib/cosense.ts` の定数。
  - ツッコミとして採用するのは、gosyujin の行だけ(許可リスト)。「エージェント以外」ではなく「人間のアカウント」で絞る。メンバーが増えても、勝手に指摘として扱われない。
  - cosense-sync は、最初にトークンの持ち主を確かめ、satoca でなければ何も送らない。
- **エージェントは Cosense に直接は書かない。**`cosense/` にファイルを書き、cosense-sync が検査してから送る(仕様書15節の提案の形)。
  - `cosense/pages/{ページ名}.txt`: 用語ページの中身。送ったあとも残す。最後に送った中身のハッシュを `state/cosense-sent.json` に持ち、変わったときだけ送る(残したままにすると、人間が直したページを毎回エージェントの版に戻そうとするため)。
  - `cosense/append/{ページ名}.txt`: ツッコミへの返信。書けるのは「yyyy年M月d日のツッコミ」のページだけ。送ったら消す。ページが無ければ送らない(ツッコミのページは人間が作る)。
- **他人が書いた行は変えない。** 用語ページは、いまの中身と望む中身を行ごとに比べ、同じ行は残して、違う行だけを足したり消したりする。消すことになる行に、エージェント以外の行が1行でもあれば、何も消さず、まだページに無い行だけを末尾に足す(仕様書の「競合したら追記に倒す」)。
- **ページの書式**(2026-11-25 にユーザーが決めた): ページ名の次の行は必ず空行。まとまりの区切りは空行1つ。ページの末尾は必ず空行1つ。エージェントの書き方に任せず、送るときに cosense-sync が整える(`formatPageBody`)。
  書式を変えたら `PAGE_FORMAT` の数を上げる。送信済みの判定に混ぜてあるので、全部の用語ページが1回だけ送り直される。
- **書かせないページ**: `settings`・`favicon`・メンバーのページ・`gi-yoza`(署名のアイコン)。ページ名はファイル名から決まるので、名前の検査で止める。
- **署名**は cosense-sync が付ける(`[gi-yoza.icon]`)。用語ページは最後の行、返信は先頭の行。
- **送る前に、出典の URL が生きているかを確かめる**(lint と同じ検査)。用語ページは、出典の URL が1つも無ければ送らない。
- **失敗しても job を止めない。** 止めると、同じ起床でエージェントが書いた日記や行動ログまで commit されなくなる。結果は journal に `- HH:MM cosense …` の行で残し、送れなかったファイルは次の起床でもう一度試す。
- **wake の読み取り**: ページの一覧から `state/known.txt`(用語ページの名前)を作る。更新のあったツッコミのページを読み、人間の行が増えた・変わったときだけ `state/inbox/` に写して、起床理由「ツッコミ 新着N」にする。エージェント自身の返信で更新されただけなら、理由にしない。
- エージェントが書ける場所に、`cosense/pages/` と `cosense/append/`(`.txt`)を足した。`state/` と `RULES.md` は、まだ書かせていない。

## 再検討するとき

- cosense-cli が依存なしで使えるようになったら、API の直接呼び出しをやめられる。
- 編集 API(`page-edit-for-ai`)の形が変わったら、`tools/lib/cosenseApi.ts` を直す。公式の文書は CLI のヘルプしか見つけていない。
- 人間のメンバーが増えたら、`HUMAN_USER_IDS` に足す。
- エージェント用のアカウントを専用のものに替えるとき(いまは流用)。`AGENT_USER_ID` と、書かせないページの一覧を直す。
