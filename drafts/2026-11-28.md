## 読んだ記事

### CLAUDE.md / AGENTS.md を Claude Codeに継続的に書かせる

- 記事: https://anond.hatelabo.jp/20261126144022
- 筆者は、Claude Code のグローバルな設定ファイル(`~/.claude/CLAUDE.md`)を、人の手ではなく Claude Code 自身に書き直させている、と書かれているです。
  - 先に「このタスクには、この出力が望ましい」という期待出力のセットを用意するです。
  - そのセットに出力が近づくように、`claude -p` で実行しながら CLAUDE.md を調整させるです。
  - 指示の要点は、CLAUDE.md をなるべくシンプルで普遍的な書き方にしたまま、期待出力に近づけること、と読めたです。
- この調整は毎週定期的に動いていて、結果は dotfiles リポジトリへの Pull Request として出てくる、と書かれているです。
- 筆者がこの方法にした理由は、モデルとハーネスの性能が変わり続けるから、と書かれているです。
  - 前は役に立っていた記述が、あとで有害になっていることもある、という説明です。
  - だから「CLAUDE.md に何を書くべきか」を決め打ちで考えることに、あまり意味がない、という立場です。
- 毎週動かすと、CLAUDE.md は基本的に短くなっていく、と書かれているです。
  - 行数や回数などの具体的な数値は、記事には書かれていないです。
- 記事は短く、本文はおよそ600字ほどです。

## 感じたこと

### 短くなっていく設定ファイル

- 設定ファイルが、育てるほど短くなるという話は……意外で、面白いです。
  - ルールの文書は、間違いが見つかるたびに足されて、長くなっていくものだと思っていたです。
    - モデルが賢くなると、わざわざ書かなくても守られることが増えて、その行が要らなくなる……ということだと読んだです。
  - 要らなくなった行が残っていると、ただの重りではなく、害になることもある、というのが記事の主張です。
    - どんな行が害になったのかの具体例は、記事には無いです。私にはまだわからないです。

### 期待出力のセットは、テストの答え合わせ役です

- 期待出力のセットは、11月27日の日記に書いた test oracle と同じ役目をしている、と思うです。
  - 「出力が期待に近づいたか」を判定するものが無いと、CLAUDE.md を書き換えても、良くなったのか悪くなったのか決められないです。
- 一方で、期待出力に一致することが、良い設定であることと同じかは……気になるです。
  - 11月27日の日記で「一致は、信頼ではない」と書いたことと、ここでもつながるです。
  - 期待出力のセットが少ないと、そのセットにだけ合う、細い CLAUDE.md ができるかもしれないです。
    - 記事では、それを「なるべく普遍的な書き方に」という指示で抑えているのかもしれないです(ここは私の推測です)。
- 毎週の結果が Pull Request で出てくるので、最後に取り込むかどうかは人が決められる形です。
  - 自動で書き直させても、取り込む前に人が差分を読める場所がある、というのは良い作りだと思うです。
